## Project

## Week 2 Scope

The Week 2 goal is to complete the prediction endpoint, strengthen validation and error handling, return probability and risk-level output, and expand API testing.

## Work Completed

- Finalized `POST /predict` around the saved-model service.
- Added probability-based `LOW`, `MEDIUM`, and `HIGH` risk classification.
- Added configurable medium and high risk thresholds with safe defaults of 0.40 and 0.70.
- Added stronger validation for missing, unknown, negative, and non-finite metric values.
- Improved handling for missing or unreadable model artifacts with HTTP 503 responses.
- Added feature count and risk-threshold metadata to prediction responses.
- Extended `GET /model/info` to expose risk thresholds and optional evaluation metrics stored in the model artifact.
- Expanded backend tests to cover successful predictions, model availability, invalid inputs, risk boundaries, probability output, feature contract, and evaluation metadata.

## Model Comparison Integration

The backend now supports optional model evaluation metadata in the saved artifact. When the ML workstream supplies metrics such as precision, recall, F1-score, and PR-AUC, `/model/info` exposes them without hard-coding research results in the API.

Expected artifact metadata shape:

```python
"metadata": {
    "evaluation_metrics": {
        "precision": 0.0,
        "recall": 0.0,
        "f1": 0.0,
        "pr_auc": 0.0,
    }
}
```

Real evaluation values should come from the finalized Logistic Regression and Random Forest experiments.
